# Supabase Backend Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the Student Coffee POS from Apps Script/Sheets live writes to Supabase-backed Next.js APIs while retaining Google Sheets as a post-close reporting export and making checkout idempotent on iPad.

**Architecture:** The existing interactive Next.js client remains the UI. Same-origin App Router Route Handlers authenticate staff sessions, validate POS commands, and call Supabase PostgreSQL with server-only credentials. Shift close commits to Supabase first and then exports a stable, idempotent snapshot to a configured Google Sheets sync endpoint.

**Tech Stack:** Next.js 16 App Router, React, JavaScript modules, Supabase PostgreSQL via `@supabase/supabase-js`, Web Crypto password hashing, Node built-in test runner, Vercel deployment, Google Apps Script retained only as a reporting sync receiver.

**Spec:** `docs/superpowers/specs/2026-08-26-supabase-backend-migration-design.md`

## Global Constraints

- Supabase is the live source of truth; Google Sheets is a reporting destination only.
- No privileged Supabase key, database password, or Google credential may be exposed to browser code.
- Checkout is unavailable while offline; no offline order queue is implemented.
- A transaction ID is generated once per checkout attempt and reused for retries.
- A duplicate transaction ID with the same payload returns the original result; a conflicting payload is rejected.
- Shift close commits even if Sheets export fails; export status is persisted for retry.
- Expense entry and Sheets-to-Supabase expense import are deferred, but the schema must leave an extension point.
- Use Next.js App Router Route Handlers under `src/app/api`; do not place a `route.js` beside `src/app/page.jsx`.
- Every production code path added by this plan gets a failing test before its implementation.

```sql
create extension if not exists pgcrypto;

create table products (
  id text primary key,
  name text not null,
  category text not null,
  price numeric(10,2) not null check (price >= 0),
  staff_price numeric(10,2) not null check (staff_price >= 0),
  active boolean not null default true,
  sort_order integer not null default 999,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table staff (
  id text primary key,
  name text not null,
  pin_hash text not null,
  role text not null default 'STAFF',
  active boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table shifts (
  id text primary key,
  staff_id text not null references staff(id),
  opened_at timestamptz not null default now(),
  closed_at timestamptz,
  mpay_expected numeric(10,2) not null default 0,
  wechat_expected numeric(10,2) not null default 0,
  mpay_actual numeric(10,2),
  wechat_actual numeric(10,2),
  difference numeric(10,2),
  note text not null default '',
  status text not null default 'OPEN' check (status in ('OPEN','CLOSED')),
  sheet_sync_status text not null default 'NOT_READY' check (sheet_sync_status in ('NOT_READY','PENDING','SYNCED','FAILED')),
  sheet_synced_at timestamptz,
  sheet_sync_error text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create unique index one_open_shift_per_staff on shifts(staff_id) where status = 'OPEN';

create table transactions (
  id text primary key,
  shift_id text not null references shifts(id),
  staff_id text not null references staff(id),
  type text not null check (type in ('NORMAL_SALE','STAFF','WASTE')),
  total numeric(10,2) not null check (total >= 0),
  payment_method text not null default '' check (payment_method in ('','MPAY','WECHAT_PAY')),
  waste_reason text not null default '' check (waste_reason in ('','MADE_WRONG','CALIBRATION','SPILLED','OTHER')),
  status text not null default 'COMPLETED' check (status = 'COMPLETED'),
  fulfillment_status text not null default 'PENDING' check (fulfillment_status in ('PENDING','COMPLETED')),
  completed_at timestamptz,
  completed_by text references staff(id),
  payload_fingerprint text not null,
  created_at timestamptz not null default now(),
  constraint transaction_payment_rules check ((type = 'WASTE' and total = 0 and payment_method = '') or (type <> 'WASTE' and payment_method in ('MPAY','WECHAT_PAY'))),
  constraint transaction_waste_rules check ((type = 'WASTE' and waste_reason <> '') or (type <> 'WASTE' and waste_reason = ''))
);

create table transaction_items (
  id uuid primary key default gen_random_uuid(),
  transaction_id text not null references transactions(id) on delete cascade,
  product_id text not null references products(id),
  product_name text not null,
  temperature text not null default '' check (temperature in ('','HOT','ICED')),
  quantity integer not null check (quantity > 0),
  unit_price numeric(10,2) not null check (unit_price >= 0),
  line_total numeric(10,2) not null check (line_total >= 0)
);

create table shift_sync_attempts (
  id uuid primary key default gen_random_uuid(),
  shift_id text not null references shifts(id) on delete cascade,
  attempted_at timestamptz not null default now(),
  status text not null check (status in ('SYNCED','FAILED')),
  response_message text not null default ''
);

create index transactions_shift_created on transactions(shift_id, created_at);
create index transactions_created on transactions(created_at);
```

**Interfaces:**
- `getSupabaseAdmin()` returns a memoized server-only Supabase client.
- `validateTransactionInput(input)` returns normalized transaction data or throws a stable validation error.
- `fingerprintTransaction(input)` returns a deterministic SHA-256 hex digest.
- `createOrGetTransaction(input, actor)` performs idempotent persistence and returns `{ transactionId, duplicate }`.
- `verifyPin(pin, encodedHash)` verifies a scrypt/PBKDF2 hash without exposing the plaintext.

- [ ] **Step 1: Write failing tests for validation and idempotency contracts**

Cover: valid normal sale, invalid payment, valid waste with zero total, invalid waste payment, same transaction ID and same fingerprint returning duplicate, and same transaction ID with different fingerprint throwing `CONFLICTING_TRANSACTION`.

- [ ] **Step 2: Run focused tests and verify expected failures**

Run: `node --test tests/server-validation.test.mjs tests/server-pos-service.test.mjs`  
Expected: FAIL because the server modules and functions do not exist.

- [ ] **Step 3: Implement validation and fingerprinting**

Normalize item fields, enforce positive integer quantities, derive line totals from submitted unit prices, enforce the three transaction types and two payment methods, and serialize a stable object with sorted item fields before hashing.

- [ ] **Step 4: Implement the Supabase admin client and password helper**

Use `createClient(supabaseUrl, serviceRoleKey, { auth: { persistSession: false, autoRefreshToken: false } })`. Implement encoded password records as `pbkdf2$iterations$salt$hash`, using Node Web Crypto with a random salt and constant-time byte comparison.

- [ ] **Step 5: Implement idempotent persistence**

Look up the transaction by `id`; if present and fingerprint matches, return `{ transactionId: id, duplicate: true }`; if the fingerprint differs, throw `CONFLICTING_TRANSACTION`. For new records, query the referenced shift and actor, insert the transaction and all item snapshots, and return `{ transactionId: id, duplicate: false }`. If a unique conflict occurs due to a concurrent request, re-read and apply the same fingerprint comparison.
